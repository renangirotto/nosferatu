title: BaseHead
description: The document metadata fragment — charset, viewport, canonical URL, Open Graph and Twitter cards — for the head slot of BaseHtml.

`BaseHead` renders the contents of a document's `<head>`: the metadata every page needs plus the social-sharing tags. It does not render `<head>` itself — it is a fragment meant for [BaseHtml](/html/base-html/)'s `head` slot — so there is no live demo on this page.

```astro
---
import BaseHead from 'astro-nosferatu/html/BaseHead.astro';
---
```

## Usage

```astro
---
import BaseHtml from 'astro-nosferatu/html/BaseHtml.astro';
import BaseHead from 'astro-nosferatu/html/BaseHead.astro';
---

<BaseHtml>
	<BaseHead
		slot="head"
		title="Nosferatu, a sympathy for the night"
		description="A worked example of the metadata BaseHead renders."
		imageSocialMedia="/og/nosferatu.png"
	/>
	<main>
		<h1>Nosferatu, a sympathy for the night</h1>
	</main>
</BaseHtml>
```

## Rendered markup

```html
<meta charset="utf-8" />
<meta name="color-scheme" content="dark light" />
<meta name="generator" content="Astro v7.4.1" />
<meta name="viewport" content="width=device-width,initial-scale=1" />
<link rel="icon" type="image/svg+xml" href="/favicon.svg" />

<link rel="canonical" href="https://example.com/posts/nosferatu/" />

<title>Nosferatu, a sympathy for the night</title>
<meta name="title" content="Nosferatu, a sympathy for the night" />
<meta name="description" content="A worked example of the metadata BaseHead renders." />

<meta property="og:type" content="website" />
<meta property="og:url" content="https://example.com/posts/nosferatu/" />
<meta property="og:title" content="Nosferatu, a sympathy for the night" />
<meta property="og:description" content="A worked example of the metadata BaseHead renders." />
<meta property="og:image" content="https://example.com/og/nosferatu.png" />

<meta property="twitter:card" content="summary_large_image" />
<meta property="twitter:url" content="https://example.com/posts/nosferatu/" />
<meta property="twitter:title" content="Nosferatu, a sympathy for the night" />
<meta property="twitter:description" content="A worked example of the metadata BaseHead renders." />
<meta property="twitter:image" content="https://example.com/og/nosferatu.png" />
```

The two image tags are rendered **only** when `imageSocialMedia` is set. Everything else is always rendered.

## Props

| Prop | Type | Required | Default | What it does |
| --- | --- | --- | --- | --- |
| `title` | `string` | Yes | — | The document `<title>`, the `title` meta, `og:title` and `twitter:title`. |
| `description` | `string` | Yes | — | The `description` meta, `og:description` and `twitter:description`. |
| `imageSocialMedia` | `string` | No | — | The sharing image, rendered as `og:image` and `twitter:image`. A relative path such as `/og/nosferatu.png` is resolved to an absolute URL; omit the prop and neither tag is rendered. |

`astro check` reports a missing `title` or `description` as a type error rather than rendering an empty tag.

## The canonical URL

The canonical link is the current page's path resolved against your project's [`site`](https://docs.astro.build/en/reference/configuration-reference/#site) setting:

```js
// astro.config.mjs
export default defineConfig({
	site: 'https://example.com',
});
```

If your project has no `site` configured, `BaseHead` falls back to the current page's own URL instead of failing the build — the page still gets a canonical link, it just cannot know your production origin. Set `site` before you ship.

## What is fixed, and how to extend it

Three values are deliberately not props:

| Fixed | Value |
| --- | --- |
| Favicon | `/favicon.svg`, as `<link rel="icon" type="image/svg+xml">` |
| Open Graph type | `website` |
| Twitter card | `summary_large_image` |

A page that needs something else — another favicon, `og:type="article"`, an RSS link, a `theme-color`, structured data — adds it through `BaseHtml`'s `head` slot, next to `BaseHead`:

```astro
<BaseHtml>
	<BaseHead slot="head" title="…" description="…" />
	<meta slot="head" property="og:type" content="article" />
	<link slot="head" rel="alternate" type="application/rss+xml" href="/rss.xml" />
	<!-- … -->
</BaseHtml>
```

`BaseHead` also loads **no font**. The library ships none, and a head component is the wrong place to make that choice for you — import your own in the page, or add a `<link>` through the `head` slot.

## Styling

`BaseHead` declares no CSS and defines no custom properties, but it does import one stylesheet on your behalf:

```astro
import 'astro-nosferatu/styles/index.css';
```

So a page whose head is `BaseHead` already has the library's tokens, palette, shadows and reset, in their declared layer order — you do not need to import them again. Everything the library contributes is inside the `nosferatu` cascade layer, so your own unlayered CSS still wins without a specificity fight.

If you want the metadata without the stylesheet, write the tags yourself; this file is deliberately the opinionated base the library's layouts are built on.
