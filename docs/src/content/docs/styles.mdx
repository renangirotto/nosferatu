## Import everything

Load `index.css` once, for example in your base layout:

```astro
---
import 'astro-nosferatu/styles/index.css';
---
```

It includes, in order:

| File | What it contains |
|---|---|
| `tokens.css` | `--nf-*` custom properties on `:root` (spacing, fonts, radius) |
| `colors.css` | `--nf-*` color palette on `:root` (light and dark scales) |
| `reset.css` | box-sizing, margin reset, `color-scheme`, `100dvh` body container, media and form-control defaults, text wrapping |
| `typography.css` | headings, paragraphs, lists, links, code |

## Cascade layers

`index.css` puts every file in its own cascade layer:

```css
@layer nosferatu.tokens, nosferatu.colors, nosferatu.reset, nosferatu.typography;
```

```
nosferatu.tokens < nosferatu.colors < nosferatu.reset < nosferatu.typography < your unlayered CSS
```

Any CSS you write outside a layer wins over the library, whatever its specificity. No `!important` needed:

```css
/* your stylesheet, loaded after index.css */
h1 {
	color: rebeccapurple;
}
```

Tokens and colors are layered too, so an unlayered `:root { --nf-… }` override wins whether it loads before or after `index.css`.

## Import single files

Each file can be imported on its own, for example to keep your own reset:

```astro
---
import 'astro-nosferatu/styles/tokens.css';
import 'astro-nosferatu/styles/colors.css';
import 'astro-nosferatu/styles/typography.css';
---
```

:::caution
Files imported on their own are **not** layered. Only `index.css` adds the `nosferatu.*` layers.
:::

## Tokens

Every value the library uses is a custom property prefixed with `--nf-`:

| Group | Tokens |
|---|---|
| Spacing | `--nf-space-1` (0.25rem), `--nf-space-2`, `--nf-space-3`, `--nf-space-4`, `--nf-space-6`, `--nf-space-8` (2rem) |
| Font family | `--nf-font-body`, `--nf-font-heading`, `--nf-font-mono` |
| Font size | `--nf-font-size-sm`, `-md`, `-lg`, `-xl`, `-2xl`, `-3xl` |
| Font weight | `--nf-font-weight-normal`, `-medium`, `-bold` |
| Line height | `--nf-line-height-body`, `--nf-line-height-heading` |
| Radius | `--nf-radius-sm`, `--nf-radius-md`, `--nf-radius-full` |

## Colors

`colors.css` holds the color palette. There are no semantic color tokens: styles and components use palette steps directly.

Each token is named `--nf-<hue>-<scale>-<step>`:

- **hue**: `blue`, `cyan`, `green`, `orange`, `pink`, `purple`, `red`, `yellow`
- **scale**: `d` for dark mode, `l` for light mode
- **step**: `10` to `100`, in tens

For example `--nf-red-l-80` or `--nf-blue-d-20`. All values are OKLCH. The library styles currently use the light (`-l-`) scale:

| Role | Token |
|---|---|
| Headings, body copy | inherited from the page — the library sets no `body` color |
| Muted text (`small`) | `--nf-blue-l-80` |
| Surface (`code`, `pre`) | `--nf-blue-l-10` |
| Links | `--nf-red-l-80` (hover `--nf-red-l-90`) |
| Components | their own `--nf-<component>-*` properties, resolved from the palette |

## Theming

Override tokens after loading the styles to re-theme the library, including components:

```css
:root {
	--nf-red-l-80: var(--nf-purple-l-80);
	--nf-red-l-90: var(--nf-purple-l-90);
	--nf-font-body: 'Inter', sans-serif;
}
```

You can also scope an override to part of a page:

```css
.promo {
	--nf-red-l-80: var(--nf-green-l-80);
}
```
