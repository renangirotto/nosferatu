# Proposal

## Why

The library has a raised control (`Button`) and a static panel (`Callout`) but nothing that hides and reveals content. Every documentation set, FAQ and settings page needs one, and the native `<details>`/`<summary>` pair already gives the behaviour, the keyboard support and the accessibility semantics for free — what it does not give is an animated open and close, which until recently needed JavaScript or a height hack. CSS now animates it natively through `::details-content`, `@starting-style` and size interpolation, so a component that ships nothing but source and no runtime can finally provide a smooth disclosure.

## What Changes

- **New `Accordion` component** (`astro-nosferatu/components/Accordion.astro`): a `<details>` element carrying a required `summary` string rendered inside its `<summary>`, a default slot rendered inside a `<div>` for the disclosed content, and the same 9-hue `color` prop as `Button` and `Callout` (rendered as `data-ui-color`, defaulting to `purple`). Native `<details>` attributes — `open` for a panel that starts disclosed, `name` for an exclusive accordion group — pass straight through, so the component adds no props for behaviour the element already has.
- **Summary styled as a `Button`.** The summary fills with `--nf-accordion-color`, takes its text, box-shadow and focus outline from `--nf-accordion-accent-color`, and reproduces `Button`'s depth: raised `4px` at rest, sunk to `2px` on hover and focus, pressed flat while `:active`, and — the one addition — held flat for as long as the `<details>` is `[open]`, so the open state reads as a button that stays pressed. The content panel below shares the same fill and accent, with `8px` block and `16px` inline padding on both the summary and the content.
- **CSS-only open/close animation.** The disclosed height animates in both directions on `::details-content`, using `calc-size(auto, size)` for the open height, `transition-behavior: allow-discrete` for `content-visibility`, and `@starting-style` so the opening transition has a value to start from. The whole animated block sits behind an `@supports` test, so a browser without size interpolation gets the plain, instant native `<details>` instead of a panel stuck at zero height. Reduced motion zeroes the duration, exactly as `Button` does.
- **New docs page** `components/accordion.mdx` with live demos of every hue, both states, the open/close animation, the `name` grouping, the theming properties and the scoped-styles check.

Consumer-visible: yes, but purely additive. A new component file under `src/components/` is published automatically by the existing `exports` map; no existing component, stylesheet, token or export changes, so nothing a consumer already depends on moves. The package manifest is untouched: still one `astro` peer dependency and no runtime dependencies.

## Capabilities

### New Capabilities

None. The component's behaviour belongs to `library-styles` and its page to `documentation-site`, exactly as `Button` and `Callout` do.

### Modified Capabilities

- `library-styles`: adds the `Accordion` content API, its color resolution through `--nf-accordion-color` and `--nf-accordion-accent-color`, its appearance and interaction states including the `[open]` pressed state, and its progressively-enhanced open/close animation.
- `documentation-site`: adds the `Accordion` page, including demonstrating the animation, the `open` and `name` native attributes, and the slot.

## Impact

- `packages/ui/src/components/Accordion.astro` (new). No other library source file changes; `ColorPalette` is reused from `src/types/components.ts` as-is.
- `packages/ui/package.json` unchanged — `exports` already maps `./components/*`, and `files` already covers `src`.
- `docs/src/content/docs/components/accordion.mdx` (new). The sidebar is autogenerated, so `docs/astro.config.mjs` is not touched.
- Browser support is the one real caveat: the animation depends on `::details-content` and on CSS size interpolation (`calc-size()`), which are not yet universal. The component is designed so that the unsupported path is the browser's own `<details>` behaviour rather than a broken panel.

## Non-goals

- **No JavaScript.** If a browser cannot animate the disclosure in CSS, it opens and closes instantly. The library has no runtime and this change does not start one.
- **No accordion group component.** Mutual exclusion is the native `name` attribute on `<details>`; a wrapper component that manages siblings would duplicate it in script.
- **No custom disclosure marker.** The native triangle stays, rotated by the browser. A replacement chevron would add a part, an icon decision and more spec surface for no behaviour.
- **No new tokens or palette entries.** Padding, radius, font size and colors all come from the tokens and palette that already exist; anything component-specific (depth, lift, duration) is a component-scoped `--nf-accordion-*` property, not an addition to `tokens.css`.
- **No change to `Button` or `Callout`**, and no extraction of a shared "raised control" rule between `Button` and `Accordion`'s summary: the library ships per-component scoped styles, and a shared stylesheet would be a new published API.
